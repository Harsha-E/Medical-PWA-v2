Product Requirements Document (PRD)
Product Name: MedCare

Platform: Offline-First Progressive Web Application (PWA)

Version: 3.0 (v3 Architecture)

Document Status: Active / Implementation Phase

1. Product Overview
MedCare is a high-performance, offline-first clinical medication environment. Engineered as a Native Progressive Web Application (PWA) without heavy framework bloat, it provides users with an encrypted, local-first platform to track medications, analyze drug interactions, and manage medical history. The application utilizes a premium "Warm Medical Luxury" design language, hardware-accelerated animations, and native-grade haptic feedback to simulate a flagship operating system experience.

2. Target Audience
Chronic Care Patients: Individuals managing complex, multi-dose daily medication schedules.

Family Caretakers: Users managing prescriptions and medical histories for dependents or elderly family members.

Clinical End-Users: Patients requiring secure, offline access to their medical data in clinical environments with poor network connectivity.

3. Core Objectives & Principles
Absolute Reliability (Offline-First): The application must function flawlessly without an active internet connection, utilizing Dexie.js for local data persistence and Service Worker caching (sw.js).

Native Illusion: The PWA must feel indistinguishable from a Swift/Kotlin native app. This includes overriding default browser behaviors (pull-to-refresh, text selection) and implementing custom momentum scrolling and haptic touch engines.

Zero-Bloat Architecture: Strict adherence to Vanilla ES6 JavaScript, HTML, and CSS. No node_modules dependency chains for the core UI layer to ensure rapid parsing and minimal memory footprint.

Clinical Privacy: Sensitive medical data is processed locally where possible, with a secure, tokenized bridge to Firebase for authenticated cloud syncing.

4. Key Features & Requirements
4.1. Progressive Web App (PWA) Engine
Autonomous Installation: A global, floating glassmorphic banner must dynamically prompt users to install the application via WebAPK (Android/Chrome) or provide fallback instructions for iOS Safari.

Strict Manifest Compliance: Must serve perfectly square 192x192 and 512x512 .png maskable icons to pass stringent OS-level PWA requirements.

App Shell Architecture: The root viewport must be locked (position: fixed, overflow: hidden) to prevent browser bouncing, while child views utilize hardware-accelerated -webkit-overflow-scrolling: touch.

4.2. Clinical Feature Set
Dashboard & Adherence: Visual daily tracking of medication schedules.

OCR Prescription Scanning: Integration with Tesseract.js (VisionPipeline) to allow users to scan pill bottles or prescriptions via the device camera.

Interaction Matrix (NLP): A local computational graph (InteractionGraph.js) that cross-references user medications against a clinical index (drug-index.json, food-interactions.json) to warn of dangerous drug-drug or drug-food interactions.

Family Profiles & Hub: Shared management of dependents' medical data.

Emergency Card: Instantly accessible critical health data and ICE (In Case of Emergency) contacts.

4.3. UI/UX Specifications (Warm Medical Luxury)
Color Palette: Deep, clinical dark mode. Backgrounds heavily utilize #050203, with warm ethereal accents of #ffd9b5 (Cream/Gold), #ffb88c (Peach/Orange), and #7f2f5d (Deep Rose).

Ethereal Aura Engine: Canvas/WebGL-driven background layers that render massive, slow-moving radial gradients that react to user pointer parallax.

Glassmorphism: Extensive use of backdrop-blur, semi-transparent borders, and deep shadow isolation to create depth.

Haptics (HapticEngine.js): Intercepts touch events to simulate 3D-touch and provides distinct vibration patterns ([30, 50, 30]) for success states and navigation.

5. Technical Architecture
Frontend Layer
Core: Vanilla ES6 JavaScript Classes (DOM manipulation, routing).

Styling: Tailwind CSS (utility classes compiled via Vite).

Graphics: Canvas API / WebGL (via Three.js / GhostFluid.js).

State Management: Custom reactive state store (core/state.js).

Data & Machine Learning Layer
Local Database: IndexedDB wrapped by Dexie.js (core/db.js).

Cloud Sync & Auth: Firebase v10 (core/firebase.js).

Machine Learning: TensorFlow.js (TFJS) for local inference and Tesseract.js for optical character recognition.

Routing / Sitemap (core/router.js)
#/install - Global PWA Installation environment.

#/landing / #/splash - Unauthenticated marketing/boot sequence.

#/login / #/register - Authentication flow.

#/onboarding - Initial medical profile setup.

#/dashboard - Primary authenticated hub.

#/scan - Camera-based OCR scanner.

#/medications & #/medication - Inventory and detail views.

#/interactions - Drug interaction graph visualizer.

#/history, #/reports, #/calendar - Adherence and historical tracking.

#/emergency - Rapid-access medical ID.

6. Security & Compliance
Data Isolation: User data must not leak into global window scopes.

Route Guarding: Unauthenticated users must be redirected to #/landing. Non-standalone users (running in a standard browser tab) must be redirected to #/install to enforce the native app environment.

Asset Integrity: Service Worker (sw.js) must prioritize cache-first strategies for HTML/JS/CSS to prevent MITM injection during offline usage.

7. Future Scope (Post-MVP)
Vibe Coding CLI: Implement natural language AI agents (Groq/Gemini) to allow users to interact with their medical data conversationally.

Mesh Network / Hydra Pool: Transition from centralized API dependencies to localized P2P mesh logic for ultra-resilient data sharing (e.g., sharing an emergency card locally via Bluetooth/WebRTC).

MedCare v3 Architecture Summary
System Paradigm: Offline-First Progressive Web Application (PWA) using a Native App Shell architecture.
Design Language: "Warm Medical Luxury" (Dark mode, glassmorphism, hardware-accelerated momentum scrolling, WebGL ethereal backgrounds).

1. Tech Stack
Core: Vanilla ES6 JavaScript (No frontend frameworks like React/Vue).

Styling: Tailwind CSS (compiled via Vite).

Local Database: IndexedDB wrapped by Dexie.js.

Cloud / Auth: Firebase v10 (Auth, Firestore).

Graphics / UI: Three.js (WebGL backgrounds like GhostFluid.js).

Machine Learning (On-Device): Tesseract.js (OCR)  , TensorFlow.js (TFJS).

Build Tool: Vite.

2. Core File Structure
/ (Root): App entry (app.js), global styles (style.css), PWA config (manifest.json, sw.js v4).

/core/: Central engines. Includes the router (router.js), reactive state (state.js), database initialization (db.js), Firebase config (firebase.js), and global visual engines (GhostFluid.js, StoryEngine.js).

/services/: Business logic and native hardware simulators. Contains PwaInstallManager.js (autonomous banner), HapticEngine.js (singleton vibration API), InteractionGraph.js, and VisionPipeline.js (OCR).

/views/: Route-level UI components (e.g., dashboard.js, install.js, medications.js). Elements are constructed natively via document.createElement and injected with innerHTML.

/data/ & /ml/: Local clinical datasets (drug-index.json, food-interactions.json) and trained models for offline NLP/Computer Vision.

3. Major Data Flows
Offline-First Strategy: The app reads and writes primarily to the local IndexedDB via Dexie (core/db.js). This ensures zero latency and offline capability.

Cloud Sync: When network conditions permit, local mutations are synced to Firebase Firestore (core/firebase.js).

Asset Caching: The Service Worker (sw.js) aggressively caches all HTML, CSS, JS, and image assets (icon-192.png, icon-512.png) to bypass network requests entirely after the initial load.

Local Inference: Vision pipelines and drug-interaction matrix calculations happen entirely on the client utilizing local JSON indexes and TFJS/Tesseract models, ensuring privacy.

4. Active State Management & Routing
State (core/state.js): Utilizes a custom vanilla reactive store. It subscribes to onAuthStateChanged in app.js. When a user authenticates, the state hydrates local user profiles and broadcasts changes to active views.

Routing (core/router.js): A hash-based router. app.js runs a strict runGuard() lifecycle on every hash change or auth state change. The guard blocks unauthenticated users from private routes and forces non-standalone (browser) users to the #/install view to enforce the native PWA environment.

2. Known Bugs & System Risks
While the fatal white-screen crashes and UI freezes have been patched, the following edge cases remain inherent to the PWA platform:

Aggressive OS Icon Caching (Ghosting): If a user installed the app while the old manifest.json (with JPEG icons) was cached, updating the icon requires the user to manually clear their browser site data. The v4 cache bump forces this for most users, but edge cases remain.

iOS Safari Install Limitations: iOS does not support the beforeinstallprompt event. We rely on a 2-second timeout to display the fallback UI ("Share → Add to Homescreen"). If Safari is heavily bogged down, this timing can feel slightly disconnected.

WebGL Context Memory: While we destroy GhostFluid instances when leaving liquid-enabled routes, rapid, repeated navigation between the auth screens and the dashboard on low-end Android devices could still trigger minor GPU memory warnings.

-- 1. USER PROFILE
-- Acts as a key-value store for user preferences and onboarding state.
CREATE TABLE userProfile (
    id INT AUTO_INCREMENT PRIMARY KEY,
    `key` VARCHAR(255) NOT NULL,
    value JSON -- Inferred: NoSQL allows arbitrary data attached to the key
);

-- 2. MEDICATIONS (Version 4 Patch)
CREATE TABLE medications (
    id INT AUTO_INCREMENT PRIMARY KEY,
    userId VARCHAR(255) NOT NULL, -- Links to Firebase Auth
    name VARCHAR(255) NOT NULL,
    dosage VARCHAR(100),
    frequency VARCHAR(100),
    startDate DATE,
    endDate DATE,
    notes TEXT,
    active BOOLEAN DEFAULT TRUE,
    INDEX (userId)
);

-- 3. DOSES (Version 4 Patch)
-- Tracks adherence logs for specific medications.
CREATE TABLE doses (
    id INT AUTO_INCREMENT PRIMARY KEY,
    userId VARCHAR(255) NOT NULL,
    medicationId INT NOT NULL,
    takenAt TIMESTAMP,
    skipped BOOLEAN DEFAULT FALSE,
    FOREIGN KEY (medicationId) REFERENCES medications(id) ON DELETE CASCADE,
    INDEX (userId)
);

-- 4. REMINDERS (Version 3)
CREATE TABLE reminders (
    id INT AUTO_INCREMENT PRIMARY KEY,
    userId VARCHAR(255) NOT NULL,
    medicationId INT NOT NULL,
    time VARCHAR(5), -- e.g., "08:00"
    isActive BOOLEAN DEFAULT TRUE,
    FOREIGN KEY (medicationId) REFERENCES medications(id) ON DELETE CASCADE,
    INDEX (userId)
);

-- 5. INTERACTIONS (Version 2)
-- Local cache of calculated drug-to-drug interactions.
CREATE TABLE interactions (
    id INT AUTO_INCREMENT PRIMARY KEY,
    drug1 VARCHAR(255) NOT NULL,
    drug2 VARCHAR(255) NOT NULL,
    severity ENUM('Low', 'Moderate', 'High', 'Severe'),
    description TEXT,
    checkedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 6. PRESCRIPTIONS (Version 3)
-- Stores Tesseract.js OCR results and images.
CREATE TABLE prescriptions (
    id INT AUTO_INCREMENT PRIMARY KEY,
    userId VARCHAR(255) NOT NULL,
    imageBlob LONGBLOB, -- IndexedDB natively stores Blob/File objects here
    rawText TEXT,
    date DATE,
    doctorName VARCHAR(255),
    INDEX (userId)
);

-- 7. MEDICAL HISTORY (Version 4 Patch)
CREATE TABLE history (
    id INT AUTO_INCREMENT PRIMARY KEY,
    userId VARCHAR(255) NOT NULL,
    type VARCHAR(100), -- e.g., 'Surgery', 'Condition', 'Vaccination'
    date DATE,
    title VARCHAR(255),
    provider VARCHAR(255),
    INDEX (userId)
);

-- 8. FAMILY PROFILES (Version 4 Patch)
CREATE TABLE family (
    id INT AUTO_INCREMENT PRIMARY KEY,
    userId VARCHAR(255) NOT NULL, -- The main account holder
    relationship VARCHAR(100),
    name VARCHAR(255) NOT NULL,
    bloodGroup VARCHAR(10),
    INDEX (userId)
);

-- 9. APPOINTMENTS (Version 4 Patch)
CREATE TABLE appointments (
    id INT AUTO_INCREMENT PRIMARY KEY,
    userId VARCHAR(255) NOT NULL,
    date DATE,
    time VARCHAR(5),
    title VARCHAR(255),
    provider VARCHAR(255),
    INDEX (userId)
);
